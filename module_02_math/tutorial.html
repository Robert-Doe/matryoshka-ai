2 · Vectors, dot products, matrices

py module_02_math\numpy_basics.py

✅ What to watch for

  • cosine similarity: cos(a,b)≈0.98 (very similar) vs cos(a,attacker) much lower. That gap is anomaly detection.
  • a matrix flips a point: [3,4] → [3,-4] via M @ point.
  • speed: numpy is ~500× faster than a Python loop for the same result. This is why ML code is "vectorized."

🛡 Security lens

Represent each session/flow/file as a feature vector; cosine similarity to a "normal" profile gives you an anomaly score. Conversely, an attacker who knows the feature space can craft inputs that look similar to normal while being malicious — the geometric intuition behind adversarial evasion, which you'll meet again in M09.

4 · Probability & Bayes (with a spam filter)

py module_02_math\probability_demo.py

The insight that will stick with you

A 99%-accurate malware scanner is only ~17% right when it alerts, because malware is rare (the base-rate fallacy). This is why "accuracy" lies on imbalanced data — the exact trap you'll disarm in Module 06, and the math behind SOC alert fatigue.

The same script then trains a Naive Bayes spam filter by hand and classifies new messages — a real classifier built from probability alone.

5 · Gradient descent: how learning actually happens

✅ Watch the ball roll

Three runs: a good learning rate converges smoothly; too big explodes out of the bowl; too small crawls. This is the most important knob in all of ML, and you're seeing it fail in three ways on purpose.
