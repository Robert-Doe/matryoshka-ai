Machine Learning Core: Supervised Learning

Learn a function from labeled examples. Regression predicts a number; classification predicts a category. Same five-step workflow for both.

⏱ ~90 min📈 scikit-learn ⚔ overfitting = the enemy

1 · The five-step workflow

SPLIT  →  TRAIN  →  PREDICT  →  EVALUATE  →  INTERPRET

Every supervised project — flowers, fraud, malware — is this loop. Read headfirst.md for the intuition; here you run it three times.

2 · Regression: predict a number, beat the baseline

py module_04_supervised\linear_regression.py

✅ What to watch for

  • The model's error (MAE) is far below the baseline "guess the average" — proof it learned.
  • The learned weights ≈ the true hidden rule (size≈50, bed≈30, age≈−20). It recovered the pattern from data alone.
  • R² near 1.0 = explains almost all the variation.

Habit for life: a model that can't beat the baseline learned nothing, however fancy it looks.

3 · Classification: the full workflow

py module_04_supervised\classify_iris.py

✅ Read the confusion matrix

Rows = true class, columns = predicted. The diagonal is correct; everything off it is a mistake. This tells you where the model errs, not just how often — the difference between "90% accurate" and "90% accurate but blind to the one class you care about."

4 · Overfitting, made visible

py module_04_supervised\train_test_split_demo.py

The table tells the whole story

ComplexityTrain errorTest errorDiagnosis
too lowhighhighunderfit (too simple)
just rightlowlowgood — learned the pattern
too high~0explodesOVERFIT — memorized the noise

The golden rule: judge a model only on data it has never seen. Train accuracy is vanity; test accuracy is truth.

🛡 Security lens — memorization is a leak

Overfitting isn't only inaccurate; a model that memorizes its training rows can be probed to reveal them (membership inference, training-data extraction). In privacy-sensitive ML, generalization is a security property. Keep that framing for Modules 10–11.
