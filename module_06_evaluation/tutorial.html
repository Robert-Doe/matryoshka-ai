Model Evaluation & Improvement (How to Not Fool Yourself)

Accuracy lies on imbalanced data. Learn the metrics that don't, cross-validate, and understand the bias–variance trade-off.

⏱ ~90 min📊 precision / recall / F1 / AUC 🛡 imbalanced = security

1 · Why accuracy lies

py module_06_evaluation\metrics_demo.py

🛡 The trap, in numbers

ModelAccuracyRecall (attacks caught)Useful?
"always benign"98%0%No — catches nothing
real detector~96%80%Yes — but LOWER accuracy

Accuracy ranks the useless model higher. On rare-event (security) data, lead with recall and precision, never accuracy alone.

2 · The four numbers everything derives from

py module_06_evaluation\confusion_matrix.py   # writes a heatmap
precision = TP/(TP+FP)   "of alarms, % real"
recall    = TP/(TP+FN)   "of real attacks, % caught"
F1        = harmonic mean of the two

Precision vs recall is a CHOICE

Favor recall when a miss is catastrophic (malware, threats). Favor precision when a false positive is costly (auto-blocking users, deleting mail). State which you optimized and why — that's rigorous evaluation.

3 · Don't trust one split — cross-validate

py module_06_evaluation\cross_validation.py

✅ Report mean ± std

  • One split swings 2–3% by luck; 5-fold CV tests every row once and gives a stable mean.
  • The std tells you how much to trust the mean.
  • Two must-dos: stratify folds (keep class balance) and keep the scaler inside the pipeline (scaling before CV leaks test info → falsely high scores).

4 · The theory: bias vs variance

py module_06_evaluation\bias_variance.py

Bias = error from being too simple (underfit); variance = error from being too sensitive (overfit). The script measures both across 200 resampled datasets: bias falls, variance rises, and the best total error sits in the middle. This is why "just use a bigger model" isn't always right.
