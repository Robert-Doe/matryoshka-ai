Data Fundamentals (AI is 80% Data Work)

Collect → clean → explore → visualize. Do this well and a simple model wins; do it badly and no model can save you.

⏱ ~75 min🐼 pandas + matplotlib 🛡 login-events dataset

1 · The pipeline you'll run

Three scripts, one flow, on a deliberately dirty dataset of login events labeled normal/suspicious:

py module_03_data\load_explore.py   # SEE the mess (EDA)
py module_03_data\clean_data.py     # FIX it, step by step, auditable
py module_03_data\visualize.py      # TELL the story with 3 plots

2 · Explore: let the data confess its problems

py module_03_data\load_explore.py

✅ The five problems it finds

ProblemSymptom in the output
Wrong typebytes_sent loads as text (an N/A is hiding in it)
Missingblank cells in bytes_sent, duration_sec, label
Duplicatesrepeated event rows
CategoriesUS vs us, normal vs NORMAL
Outliersnegative bytes/duration; 1,000,000-byte events; 999s

3 · Clean: fix each problem, auditable

py module_03_data\clean_data.py   # writes clean_data.csv

Each step prints what it changed. That audit trail is not optional in research — silent data edits destroy reproducibility. Key judgment calls:

  • Missing label → drop the row. You can't learn from an example with no answer.
  • Missing numbers → fill with the median (robust to outliers, unlike the mean).
  • Negative values → delete (impossible = data error).
  • Giant bytes_sent → KEEP. That outlier is the attack you want to detect. Domain knowledge, not a blanket rule, decides.

🛡 Security lens — data poisoning

An attacker who can inject rows into your training data can plant a backdoor without ever touching the model. The exact checks you run here — type validation, dedup, outlier and range sanity — are your first defense against poisoned training sets. Cleaning IS a security control.

4 · Visualize: three questions, three plots

py module_03_data\visualize.py   # writes PNGs into plots/

What each plot decides

  • Histogram of bytes_sent → are there distinct populations? (Yes — normal cluster + exfil tail.)
  • Failed attempts by label → is this feature useful? (Yes — suspicious fail far more.)
  • duration vs bytes scatter → are classes separable? (Yes — a feasibility check BEFORE you model.)

5 · The two ideas that will save you most often

Garbage in, garbage out. A model learns whatever is in the data, including the mistakes.
Data leakage. If future info or the answer sneaks into features (a duplicate in both train and test; a feature derived from the label), your notebook score is a lie. You'll fight leakage directly in Module 04.
